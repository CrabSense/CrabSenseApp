# P1.1 P0.2 — History corrections and lot lifecycle

Manager history correction dialog on Crab Detail > History and Box Detail > History. Fetch real allocations, moltings and box-status records; restrict actions to boxes in the selected assigned area. Rows without an attributable box are not offered for correction. Require reason; never close open allocation through correction. Backend explicitly rejects permanent deletion of both allocation and box-status history, even closed records: no delete controls. Molting void preserves audit; show void status/reason and exclude voided events from the growth count. Corrections do not change observed live state.
Lot detail: dedicated close endpoint with disposition, show closedAt, closeDisposition and returned snapshot counts. Allocation completed is not lifecycle closed. Delete only when no placed crabs and not closed; BE checks all references. Cancel and update guards reject closed and partial-scope lots. Warn on shared-lot metrics.
Test: open a test Manager account, correct note/time on existing allocation, confirm open allocation cannot be closed, correct/void molting with reason, correct box audit without changing live box, close lot after recording disposition, verify snapshot survives reload and cannot be changed, delete unused lot and verify BE rejects referenced lots. Switch areas while dialogs open. Staff APIs remain unchanged.
